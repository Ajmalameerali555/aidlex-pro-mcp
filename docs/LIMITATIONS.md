# Explicit implementation boundaries

1. **Not live yet.** This ZIP does not create DigitalOcean infrastructure, DNS, an identity-provider account, a database or a publicly registered plugin. No valid production URL is claimed.
2. **Not a human advocate.** Structured strategic analysis and adversarial review are workflows, not licensed experience, representation, court access or a guarantee of correctness/outcome.
3. **Not a complete legal corpus.** Bundled knowledge contains an internal research map and a source directory. Internal assertions, dates and article references remain unverified. Official legal text must be retrieved/ingested and its scope, amendments and applicability checked for the actual issue.
4. **Origin verification is narrower than legal verification.** `official_retrieved` proves this server fetched content from an approved origin at a recorded time. `verifiedOnly` also applies freshness filtering. Neither establishes that a statute is still effective, that an article supports the claim, or that a page is a binding authority. `legal_effect_verified` remains false.
5. **Case ingestion accepts extracted text/pages, not binary attachments.** No OCR, PDF/DOCX conversion or archive ingestion endpoint is implemented. The host must extract the file and preserve page numbers, mark unreadable areas and verify important wording against page images. An attachment ID is not file content.
6. **Host packages are not completed reports.** In host mode the client must perform the requested reasoning using the returned evidence and instructions. Server mode requires a configured supported API model and separately granted billable-analysis scope.
7. **Large cases are bounded.** A document ingestion is limited to 200,000 characters and 500 numbered pages. Default analysis includes 50,000 document characters plus bounded retrieved law and memory. Omitted pages, spans and memory items are exposed. Fetch/review omitted records and narrow the task; do not call a partial package an end-to-end review. Handoff blocks incomplete context.
8. **Retrieval is bounded.** BM25 ranks a bounded database candidate set (default 10,000 chunks). Optional vectors are stored in JSON and ranked in-process, not a scalable pgvector index. No mass legal crawl or exhaustive semantic recall claim is made.
9. **Timelines have limits.** Local mode extracts explicit date mentions and source excerpts, not semantic event resolution. Slash-form dates can be ambiguous. A local `disputed=false` value means dispute status was not assessed, not that both parties agree. Server mode needs the model and exact-quote checks but still requires human review.
10. **Draft handoff is not filing.** The handoff enforces schema and confirmation gates; it does not independently certify legal authorities just because a caller supplies an empty verification list. ChatGPT/your drafting client must verify legal support, create the document and obtain final approval. Arabic DOCX/PDF output remains the host's responsibility.
11. **No automatic existing-app integration.** Canonical tool names and schemas are preserved, but the original mobile client, Edge Functions and Supabase data are not migrated or connected automatically. Use a separately reviewed adapter for that work.
12. **Native MCP implementation.** The code implements the documented bounded stateless transport directly, not an official SDK runtime. It does not support SSE subscriptions, tasks, server sampling, binary resource streaming or automatic reconnect/resume sessions. Official-SDK and real ChatGPT interoperability must be checked before public submission.
13. **No Company Knowledge eligibility claim.** The private tools are not a claim of implementing ChatGPT's standard company-knowledge `search`/`fetch` contract with publicly openable document URLs.
14. **External production checks outstanding.** Docker build, clean network dependency installation, PostgreSQL execution, managed OAuth, real model calls and cloud deployment were not run in this environment. See VERIFICATION.md for exactly what was tested.
